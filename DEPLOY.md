# Deploying Analysis of Karma to A2 Hosting

This is a single-page website (`index.html` + `assets/app.js`) backed by a small
PHP + MySQL API for saving your content, handling the contact form, and storing
uploaded images. Every page is also rendered on the server (`render.php`) so
search engines and AI assistants see your real content. Follow these steps once
to go live.

> **Already live?** Skip to **[Upgrading the live site](#upgrading-the-live-site-seo--security-release)** at the end.

---

## What's in this folder

| File / folder        | What it does                                                        |
|----------------------|---------------------------------------------------------------------|
| `index.html`         | The page template (head, styles, script tags).                      |
| `assets/app.js`      | The website application (all pages, editor and admin).              |
| `assets/hero3d.js`   | The 3D hero scene (loaded when the browser is idle).                |
| `assets/*.webp/png/jpg` | Logo, favicons and the social-sharing image.                     |
| `render.php`         | Renders every page on the server: titles, descriptions, structured data, real content, 404s and redirects. |
| `.htaccess`          | Apache rules: https + www, clean URLs, private files, caching, security headers. |
| `uploads/`           | Where photos you upload in the admin are stored.                    |
| `api/config.php`     | **Your database + email settings — you must edit this.**            |
| `api/db.php`         | Database connection + shared helpers (admin session, CSRF).         |
| `api/auth.php`       | Admin login (hashed password, lockout after repeated failures).     |
| `api/data.php`       | Saves/loads all your site content to MySQL.                         |
| `api/seo-lib.php`    | Shared SEO engine used by render.php, the sitemap and llms.txt.     |
| `api/defaults.json`  | Default content used until something is saved (generated by `tools/build-defaults.js`). |
| `api/robots.php`, `api/sitemap.php`, `api/llms.php`, `api/indexnow.php` | Live `/robots.txt`, `/sitemap.xml`, `/llms.txt`, `/llms-full.txt` and IndexNow. |
| `api/seo-health.php` | The Admin → SEO Health scorecard.                                   |
| `api/contact.php`    | Emails contact-form messages to you and logs them.                  |
| `api/test-email.php` | Sends a test email (used by the admin's "Send test email" button).  |
| `api/upload.php`     | Receives uploaded photos and stores them in `uploads/`.             |
| `install.php`        | Run **once** to create the database tables, then delete it.         |
| `sitemap.xml`, `robots.txt` | Static backups, only used if `.htaccess` rewriting is unavailable. |
| `tools/`             | Developer helper (not needed on the server; blocked by `.htaccess`). |

## Step 1 — Create a MySQL database

1. Log in to your A2 Hosting **cPanel**.
2. Open **MySQL® Databases**.
3. Under *Create New Database*, enter a name (e.g. `analysisofkarma`) and click **Create Database**.
4. Under *MySQL Users → Add New User*, create a user and a strong password. **Write these down.**
5. Under *Add User To Database*, select your user + database, click **Add**, then tick **ALL PRIVILEGES** and **Make Changes**.

> A2 usually prefixes names with your cPanel account, e.g. `cpaneluser_analysisofkarma`
> and `cpaneluser_dbuser`. Use the full prefixed names.

---

## Step 2 — Edit `api/config.php`

Open `api/config.php` and fill in the four database values from Step 1, plus your email:

```php
define('DB_HOST', 'localhost');                 // A2 uses localhost
define('DB_NAME', 'cpaneluser_analysisofkarma');
define('DB_USER', 'cpaneluser_dbuser');
define('DB_PASS', 'the-password-you-set');

define('MAIL_TO',   'analysisofkarma@gmail.com'); // fallback recipient
define('MAIL_FROM', 'noreply@analysisofkarma.com'); // fallback From (an address on YOUR domain)

define('ALLOWED_ORIGIN', 'https://www.analysisofkarma.com'); // your live domain
```

> **You don't have to get the email exactly right here.** `MAIL_TO` and `MAIL_FROM`
> are just *fallback* defaults. Once the site is live you can set the recipient and
> the From address — and send a **test email** — directly in
> **Admin → Settings → Email settings** (see Step 5b). No file editing needed.

> **Tip:** For best delivery, create `noreply@analysisofkarma.com` as a real
> mailbox/forwarder in cPanel → *Email Accounts*, and use it as your From address.
> Sending "from" a Gmail address you don't control on the server can land in spam.

---

## Step 3 — Upload the files

Using cPanel **File Manager** (or FTP/SFTP), upload **everything in this folder**
into your domain's web root — usually `public_html/`:

```
public_html/
├── index.html
├── render.php
├── .htaccess
├── install.php
├── sitemap.xml
├── robots.txt
├── assets/
├── uploads/
└── api/
```

> `.htaccess` is a "hidden" file — in File Manager, tick **Settings → Show Hidden Files**.
> If your old `.htaccess` had cPanel PHP handler lines, paste them into the marked
> block at the top of the new one before uploading.

Make sure the **`uploads/` folder is writable** (permissions `755`, which is the default).

---

## Step 4 — Create the database tables

1. In your browser, visit:
   `https://www.analysisofkarma.com/install.php`
2. It will tell you to add a key. Visit the URL it shows
   (`install.php?key=setup_xxxxxxxx`).
3. You should see **"Tables created successfully."**
4. **Delete `install.php`** from the server (File Manager → right-click → Delete).
   Leaving it up is a security risk.

---

## Step 5 — Go live & log in

1. Visit `https://www.analysisofkarma.com` — your site is live.
2. Go to `https://www.analysisofkarma.com/admin` to open the admin panel.
3. Log in with the default password **`admin123`** (a brand-new install only).
4. **Immediately change it:** Admin → **Settings → Security → Change password**.
   The password is stored only as a secure hash on the server.

Everything you edit in the admin (text, photos, services, blog posts, SEO, etc.)
is now saved to your MySQL database, so it persists across devices and visitors.

### Step 5b — Set up and test email

1. In the admin, open **Settings → Email settings**.
2. **Send enquiries to** — the address where you want to receive contact-form messages.
3. **From address** — ideally an address on your own domain (e.g. `noreply@analysisofkarma.com`).
4. Click **Save changes**.
5. Click **✉ Send test email**. Within a minute you should receive a test message at the
   recipient address (check the spam folder too).
   - **Got it?** Email is working. 🎉
   - **"mail() failed to send"?** Your host may need PHP mail enabled — contact A2 support,
     or switch the From address to one on your own domain.
   - **Nothing arrives but no error?** Almost always a spam filter or a From address that
     isn't on your domain. Fix the From address and test again.

## Step 6 — Submit to search engines (optional but recommended)

Your **sitemap is dynamic** — `https://yourdomain.com/sitemap.xml` is generated live
from the database every time it's requested, so it **always** lists every current page
plus all **published blog posts** (e.g. `/blog/your-post-slug`). You never have to
regenerate it manually when you add or remove pages/posts.

In the admin, open **Search Engines** to:
- See the live sitemap and the current URL count (pages + posts).
- **↻ Update sitemap now** — writes a static backup copy and confirms the count.
- **Auto-update** — optionally refresh the backup daily / weekly / monthly.

Then submit it **once**:
- **Google Search Console** — verify your domain, submit `https://yourdomain.com/sitemap.xml`.
- **Bing Webmaster Tools** — same.

Because the sitemap is dynamic, Google/Bing re-read it on every crawl — new posts and
pages appear automatically, no resubmission needed.

> The dynamic sitemap relies on Apache `mod_rewrite` (the same module that powers the
> site's clean URLs). It's enabled by default on A2 Hosting.

## How it works (plain English)

- **Your content** lives in MySQL (table `aok_site_data`). When you edit the site
  in the admin, it saves to your browser instantly *and* pushes to the database a
  moment later. When anyone opens the site, it loads the latest from the database.
- **Contact form** submissions are emailed to your `MAIL_TO` address via PHP and
  also stored (table `aok_leads`) so you never lose one. The form has a math
  captcha, a honeypot, and a 30-second cooldown to block spam bots.
- **Uploaded photos** are saved as real image files in `uploads/` and referenced
  by URL — so large images never overflow browser storage.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Blank page | Check the browser console. Ensure `index.html` is at the web root and React CDN isn't blocked. |
| "Tables" error on install | Re-check the 4 DB values in `api/config.php`. The user must have ALL PRIVILEGES. |
| Edits don't persist across devices | Open `https://yoursite/api/data.php` directly — it should return JSON, not a PHP error. If it errors, fix DB config. |
| Contact emails not arriving | Use **Settings → Email settings → Send test email** to diagnose. Check spam, use a From address on your own domain, and confirm A2 has `mail()` enabled. |
| Photo upload fails | Ensure `uploads/` exists and is writable (755). Max size is 5 MB (set in `config.php`). |
| Want a different admin password | Admin → Settings → Security → Change password. |
| "Too many attempts" at login | 8 wrong passwords lock that connection for 15 minutes. Wait, then try again. |
| Forgot the admin password | In cPanel → phpMyAdmin, empty the table `aok_auth` (Operations → Empty). The next login then accepts `admin123` — change it straight away. |
| Pages show the site but Google sees no content / every URL 404s | `.htaccess` or `render.php` is missing. Upload both; check Admin → SEO Health → Crawl files. |
| Site broke right after uploading `.htaccess` | Put your old `.htaccess` back (or rename the new one to `.htaccess-off`) — the site works as before, with the admin at `/#admin`. Then check the PHP handler lines at the top. |

## Updating the site later

Just edit content through the admin panel — no re-deploy needed. If a code update
changes files, upload only the files listed in that update. Your database content
and `api/config.php` are untouched.

## Upgrading the live site (SEO & security release)

This release adds server-side rendering, local-SEO and AI settings, and fixes a
security issue. Your content, photos, leads and password all carry over.

> ⚠️ **Security note.** Until now, the site's public data file
> (`/api/data.php`) also contained the admin password and the contact-form leads
> (names, emails, birth details). Anyone who knew where to look could read them.
> After this upgrade both are private. **Change your admin password after
> upgrading**, because the old one was publicly readable.

**1. Back up first.** In cPanel → File Manager, download your current
`public_html/.htaccess` (if any) and `api/config.php`. In the admin, use
Settings → Backup → **Export content**.

**2. Upload these files** (overwrite when asked). **Do not upload `api/config.php`**
— keep your live one.

```
index.html          render.php          sitemap.xml        robots.txt
assets/app.js       assets/hero3d.js    assets/og-image.jpg
assets/logo-512.png assets/logo-512.webp assets/logo-192.webp
assets/favicon-32.png assets/favicon-48.png assets/apple-touch-icon.png
api/db.php          api/auth.php        api/data.php       api/upload.php
api/test-email.php  api/health.php      api/seo-lib.php    api/defaults.json
api/sitemap.php     api/robots.php      api/llms.php       api/indexnow.php
api/seo-health.php
```

**3. Upload `.htaccess` last.** Open the new `.htaccess` first: if your old one
had lines between `# php -- BEGIN cPanel-generated handler` and
`# php -- END cPanel-generated handler`, paste them into the marked block at the
top. Then upload it (File Manager → Settings → Show Hidden Files to see it).

**4. Log in at `https://www.analysisofkarma.com/admin`** with your **current**
password. On this first login the server stores it as a secure hash and removes
the readable copy from your site data. Nothing is reset and you are not locked out.

**5. Change your password** — Settings → Security → Change password.

**6. Fill in the new tabs** (everything is pre-filled; check and Save):
- **Local & Business** — phone (use the one on your Google Business Profile),
  hours, Maps CID link, review link, other listings.
- **Practitioner** — your bio, training and profiles.
- **AI & GEO** — which AI assistants may read your site; IndexNow.
- **Redirects** — review possible duplicate services and posts. Nothing is merged
  unless you click a merge button, and every merge can be undone.

**7. Open Admin → SEO Health.** The "Crawl files" group should be all green. If
not, `.htaccess` or `render.php` didn't upload — see Troubleshooting.

**8. Hard-refresh** (Ctrl+Shift+R / Cmd+Shift+R) and browse the site. Then in
Google Search Console and Bing Webmaster Tools, resubmit
`https://www.analysisofkarma.com/sitemap.xml` once.

### For developers

- No build step. `assets/app.js` is plain JavaScript (React 18 UMD, `React.createElement`).
- After changing default content in `assets/app.js`, run `node tools/build-defaults.js`
  to refresh `api/defaults.json` (the server's copy of the defaults).
- `render.php` adds `?v=<file time>` to `/assets/*.js` automatically, so browsers
  always load the newest scripts.
